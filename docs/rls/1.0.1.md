## Release 1.0.1 – Changelog Summary

This patch release hardens archive extraction, lifts the entire codebase and test suite to PHP 8.3–8.5 without any deprecation, notice, or warning, and makes the installer fully usable outside the original Docker layout.

* **ZIP Path-Traversal Hardening (Zip Slip)**
  Adds `isZipEntryPathSafe()` and `openZipForSafeExtraction()` in the new `ZipSecurity` helper. Every archive entry is validated against empty names, NUL bytes, absolute Unix paths (`/etc/passwd`), absolute Windows paths (`C:\…`), and `..` segments **before** any file touches disk; the whole archive is rejected on a single bad entry (fail-closed). `updateUpdaterFromTag()` now iterates entries manually via `ZipArchive::statIndex()` + `getFromIndex()` instead of `extractTo()`, enforces exactly one top-level directory, skips symlinks during iteration, and verifies every computed target path with `realpath()` against the resolved destination.
  Malicious zipballs can no longer escape the installer or the project directory.

* **Tar Path-Traversal Hardening (Tar Slip)**
  Adds `isTarEntryPathSafe()` and `validateTarArchiveForPathTraversal()` in `ProjectPackageArchiveExtractor`. Every entry name is validated **before** extraction via either `tar --list` (when the binary is available) or a unique-per-call Phar decompression, and `copyExtractedDirectory()` now also skips symlinks and re-checks `realpath()` paths against the resolved source/target.
  Malicious `.tar.gz` packages can no longer write outside the project tree.

* **Archive Extraction Tests**
  Ships `tests/ZipSecurityTest.php` with 9 tests / 30 assertions covering valid paths, `..` segments, absolute Unix and Windows paths, NUL-byte injection, malicious ZIP archives, malicious `.tar.gz` archives built by hand, and successful safe extractions.
  The dangerous attack vectors are now codified in the test suite so regressions fail CI immediately.

* **Path-Traversal Failure-Closure in `extractZip`**
  Switches the zipball extraction loop from `$zip->extractTo()` to a manual `statIndex()`/`getFromIndex()` walk, validates entry paths before writing each one, forces exactly one top-level archive directory, and uses `realpath()` + `str_starts_with()` checks to keep the resolved target path inside the resolved target directory.
  Both installer self-updates and project updates are now hardened against Zip-Slip-style archives.

* **PHP 8.3–8.5 Compatibility, Zero Deprecations**
  Replaces every `curl_close()` call with `unset($ch)` (no-op since PHP 8.0, deprecation-free), drops every `ReflectionMethod::setAccessible()` call (no-op since PHP 8.1, deprecation-free), switches the `name` and `description` of the oakengine installer `composer.json` from the symfony-git-installer copy-paste, and pins the PHP requirement to `~8.3.0 || ~8.4.0 || ~8.5.0`.
  The whole project now passes `composer test` with zero deprecations, zero notices, and zero warnings on PHP 8.5.

* **Strict PHPUnit Configuration**
  Adds `failOnDeprecation="true"`, `failOnNotice="true"`, `failOnWarning="true"`, and `error_reporting=-1` to both `phpunit-no-coverage.xml.dist` and `phpunit-coverage.xml.dist`, plus a new `bin-phpunit-strict` composer script that the default `test` / `ci` / `ci-fix` scripts now use.
  Any new PHP deprecation that lands in the codebase fails the test run, not just prints a warning.

* **Docker-Independent Test Execution**
  Replaces every hardcoded `/app/…` path in tests with `sys_get_temp_dir()` plus `pathsToDelete` cleanup, fixes the `testRunHandlesPostSaveEnv` save flow by introducing `InstallerApplication::resolveTargetDirectory()` and `resolveTargetDirectoryAbsolute()` that clamp `../../../../` segments that would otherwise escape the project root, and introduces the new `github_cache_directory` config key so tests can fully control the GitHub-refs cache location without touching `/app/var/cache/github-api`.
  The whole test suite now runs and passes without Docker, on any host with PHP 8.3+.

* **Unified Modular Class Layout**
  Splits the originally-monolithic `src/index.php` into `src/app/{Translation, Filesystem, Authenticator, GitHubClient, GitHubRefsCache, InstallUuidManager, AppSecretManager, EnvLocalManager, FilesystemSupport, MigrationStatus, InstallerUpdater, ZipSecurity, HtmlRenderer, InstallerApplication}.php`, each loaded in dependency order, with `src/index.php` reduced to a thin bootstrap that just requires the classes and runs `InstallerApplication` in non-CLI mode.
  The installer is now unit-testable piece-by-piece instead of one giant `index.php`.

* **Modern Dashboard UI (HTML Renderer)**
  Ports a fully responsive dashboard with a navigation rail (Home, Installations, Environment, Databases, Install-UUID, System, Installer), welcome cards, info lists with Lucide icons, custom dropdown widgets, confirmation modals, CSS variables with automatic light/dark mode, and an oakengine-branded welcome flow.
  The installer is now pleasant to use from a phone or a desktop, with no emojis left over from the previous text-heavy version.

* **Install-UUID & App-Secret Lifecycle**
  Adds `InstallUuidManager` (UUID v7 generator seeded from `microtime`) and `AppSecretManager` (32-char hex secret), both backed by `.env.local` parsing helpers that recognise `INSTALL_UUID=` and `APP_SECRET=` lines and validate the secret charset (16–128 chars, `[A-Za-z0-9._-]`). The dashboard exposes a dedicated “Install UUID” view with regenerate and edit-in-place actions.
  Servers always have a valid, fresh UUID/secret pair on first boot and admins can rotate either without editing files by hand.

* **Multi-Language UI Refresh**
  Brings all 12 bundled languages (en, de, es, fr, it, ja, ko, nl, pl, pt, ru, zh) up to a shared key set covering the new dashboard, install-uuid, app-secret, system, installer-management, cleanup-warnings, and migrations-failure keys. Removes all legacy emoji prefixes so the new Lucide-icon UI does not double up.
  No user sees half-translated buttons or duplicate icons in their locale.

---

**Compatibility**: Drop-in compatible with 1.0.0. No database, manifest, or config migration required. Run `composer test` to verify the upgrade locally.
